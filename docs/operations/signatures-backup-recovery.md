# 전자서명, 재승인, 백업과 복구

CAPA와 조사는 초안, 검토 요청, 승인/반려, 재승인 필요 상태를 사용합니다. 승인자는 승인 의미와 대상 버전을 확인하고 현재 인증정보와 사유를 제출합니다. 작성자 자기 승인과 권한 없는 승인은 서버에서 차단합니다. 비밀번호는 URL, 화면 상태, 로그, DB와 서명 레코드에 저장하지 않습니다.

서명 후 중요 필드를 변경하면 기존 서명을 무효화하고 승인 버전을 증가시켜 재검토·재승인을 요구합니다. 비밀번호 재인증은 기술적 통제이며 법적 전자서명 요건 충족을 자동으로 의미하지 않습니다. 필요하면 조직 IdP의 MFA 재인증 adapter로 교체합니다.

백업·복구 절차:

1. PostgreSQL과 암호화된 비공개 객체 저장소를 일관된 시점으로 백업합니다.
2. HMAC 과거 키와 KMS 키는 별도 복구 절차와 접근통제로 보관합니다.
3. 격리 환경에 DB와 객체를 복구합니다.
4. `verify_audit_chain`과 `check_audit_key_rotation`을 실행합니다.
5. 서명 데이터 해시, outbox 미전송 건, 파일 SHA-256과 객체 존재 여부를 표본 또는 정책 범위 전체에서 확인합니다.
6. 불일치나 `KEY_UNAVAILABLE`가 있으면 운영 전환하지 않고 보안·RA·QA에 보고합니다.
